# Round 1 — mathematics (discrete dynamics, symbolic dynamics, CA theory)

## 1. The project in my words
A finite 2D lattice of 128-bit cells is updated by a composition of three maps: a bit-conserving pairwise exchange (Kawasaki-like, per bit plane), a hashed majority filter, and a cellwise map f: {0,1}^128 → {0,1}^128 given by a Brotli-like decoder against a fixed dictionary. All "randomness" is a fixed hash of local contexts, so the global map is deterministic. The claim is that f is a "tame" program — analysable by sampling, census and inversion — yet the lattice reproduces species, invasion and coexistence, so those phenomena need entropy reduction, not computation.

## 2. Strengths
- The bound H(f(U)) ≤ E[min(τ,128)] = 93.5 bits (decoder-map.md §1) is correct and nicely argued: the decoder reads fair bits up to a stopping time τ, so H(X^τ) = E[τ] exactly; wrap rereads add nothing. This is the cleanest theorem-like statement in the project.
- The Gray-code construction (design-gray3.md §1) is a genuine *inverse* construction: h = H0 | (g(k)<<4) with H0's bits 4–6 clear makes consecutive headers differ in one bit, and the reflected 3-bit Gray sequence is cyclic. Verified bit-exactly for 24 states. Prescribing the attractor set of a CA's local map is rare and worth foregrounding.
- The bit-exact JS reference (decode36.mjs, 75 lines) checked against the wasm on 1.6 M cells makes every map-level claim checkable.
- The "never-read" byte range 4,095–4,335 (decoder-map.md §3) is an exact, free neutral control.

## 3. Concerns, ranked
1. **False sentences about the decoder in the draft.** INTRODUCTION.md l.50–53 / draft PDF p.1: "reads every input bit once and never reads its own output; it has no loop". decode36.mjs l.18 copies from the output (`d <= opos`), and decoder-map.md §1 measures 18.2 % of output bytes copied from the output; 5.0 % of cells at V=4096 read past bit 128, i.e. reread bits through the wrap (l.9, `cbp & WM`). There are `while` loops, bounded by the 1,024-bit cap. The true statements are: bounded work per cell, no unbounded loop, no reading of state outside the current cell's stream/output.
2. **"No fixed points" is false for the dictionaries used.** Intro l.55–56 says "for the dictionaries used here … no fixed points"; cycles.md shows fixed points for Brotli 9, Brotli 13 (295/10,000), Swarm A, Swarm D, and replicators.md has a Brotli-12 fixed point *winning* under the frame. Even for F, 10⁴ starts only shows no fixed point with basin ≳ 3·10⁻⁴; fixed points with tiny or singleton basins are invisible to sampling. "Short cycles within a few tens of turns" is also false for the texts (182-cycles, transients up to 431/670).
3. **Image-size statements reversed.** decoder-map.md §1(a): "the image of f has at most 2^93.5 elements in entropy terms". Entropy bounds |Im f| from *below* (|Im f| ≥ 2^H). Likewise §6 calls log₂|B⁸| "the exact H(f(U))"; that is log of the image size, equal to H only if f(U) is uniform on the image, which it is not. "On average ≥ 2^34 preimages" should be H(U | f(U)) ≥ 34.5 bits.
4. **"Fixed-depth", "enumerated and inverted", "O(n) vs O(c^n)".** Any map on a finite set is fixed-depth; the claim only has content as a family in the cell size n (and dictionary size). Nothing on 2^128 is "enumerated". What is actually done is sampling forward and (in design-dict.mjs) constructing preimages by grammar search. Say exactly that; the preimage search could be made a real result (see §5). INTRODUCTION_MOTIVATION.md l.217 already has the right correction; the Introduction does not use it.
5. **"Deterministic cellular automaton" needs qualifiers.** With gradients the local rule depends on the column and row (a non-uniform CA); with the default 'rotate' swap order (lattice.html l.261, band.js l.29) and the turn-parity edge pairing it is periodic in time with period 4; the grid is finite with clamped edges; mutation, if on, is salted by the turn. Correct statement: under uniform parameters, the 4-turn block map is a uniform, deterministic CA (finite grid, fixed boundary). Also docs/lattice.md §"The swap order" still describes the fixed order UD0 LR0 UD1 LR1 as the only one, contradicting METHODS.md and the page default.
6. **Basin vs lattice dynamics.** replicators.md uses basins of f on *uniform* random cells and a waiting time 1/(Nb). In the lattice the inputs to f are not uniform and not independent across turns; 1/(Nb) assumes a fresh uniform draw per cell per turn. The detector (period k over 2k turns) finds lattice-periodic cells, not certified f-cycles. "Falls roughly as the inverse square root of the basin" rests on four points from different dictionaries.
7. **Shuffle controls vs selection.** F was chosen by a swarm search. With one sample per shuffle (ablation-structure.md §1), "byte order sets the cycle" is shown, but "F's 3-cycle is atypical" needs the distribution of cycle structure over many shuffles. Random-mapping heuristics say a map that behaves randomly on an effective set of size M has cycles ~√(πM/8). Cycles of 3–30 mean M is ~10–10³ after iteration (matching "4 distinct contents" in −−R). The contraction is in the iterates, not in H(f(U)).

## 4. Questions for the other panelists
- Physicist: is "pinning by quenched disorder" right when the disorder is a function of the dynamical state (hash of contexts), not of the site? That seems closer to a deterministic self-generated glassiness.
- ALife: in the systems compared, is "replicator = attractor of a map" ever not true? If it always is, the claim is a definition, not a finding. The interesting difference is copy into a *neighbour* (non-local) vs recovery in place.
- Compression: is there a precise sense (e.g. the decoder as a finite-state/sequential transducer with bounded lookback) in which it is "not computation"? I would like a class name, not a negation.
- Statistics: how many shuffles and seeds would a census comparison need?

## 5. What I will examine in depth
- Compute H(f^k(U)) for k = 1..40 (plug-in plus coincidence estimators) for F, a shuffle and hash:93. I expect the decoder to collapse fast where the random-map null does not; that would be the right "decoder is tame" theorem.
- An exact fixed-point search for F: f(x) = x as a constraint problem over command parses (the header and the first commands fix most bytes). This settles "no fixed points" exactly.
- Check whether the Gray construction's cycle states are isolated in Hamming space, i.e. whether the funnel claim (1-bit return mean 1.5) holds for 2-bit flips.
- Write a precise definition of the global map (local rule, radius, period, boundary) and check it against band.js/lattice.wat.
- What would change my mind on concern 6: lattice runs where detected cycles are verified as f-cycles, plus a waiting-time model fitted to the actual input distribution.
